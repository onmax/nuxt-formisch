`<FAutoForm>` reads a Valibot object schema and renders a Nuxt UI input for each entry, with labels, help text, required markers, validation errors and a submit button. It is a Formisch form underneath, so validation and the submitted output are the same as with [`useForm`](/forms/composables#useform). It's registered when `@nuxt/ui` is in `modules`.

```vue [app/pages/profile.vue]
<script setup lang="ts">
import * as v from 'valibot'

const ProfileSchema = v.object({
  name: v.pipe(v.string(), v.minLength(2)),
  email: v.pipe(v.string(), v.email()),
  age: v.pipe(v.number(), v.integer(), v.minValue(18)),
  role: v.picklist(['developer', 'designer', 'manager']),
  newsletter: v.boolean(),
})

async function save(profile: v.InferOutput<typeof ProfileSchema>) {
  await $fetch('/api/profile', { method: 'PUT', body: profile })
}
</script>

<template>
  <FAutoForm :schema="ProfileSchema" :initial-input="{ name: 'Ada' }" @submit="save" />
</template>
```

The handler gets `(output, event)`, with `output` typed from the schema. It's awaited, so the submit button shows a loading state until your request finishes. If it throws, the message shows under the form.

## Props

| Prop | Type | Default | |
| --- | --- | --- | --- |
| `schema` | Valibot object schema | | Required. |
| `initial-input` | Partial schema input | | Starting values. |
| `field-config` | `Record<string, FieldConfig>` | | Per-field options, keyed by dotted path. See [Customization](/auto-form/customization). |
| `columns` | `1 \| 2 \| 3 \| 4` | `1` | Grid columns for top-level fields and array items. One column on small screens. |
| `disabled` | `boolean` | `false` | Disables every input and the submit button. |
| `validate` | `ValidationMode` | `'submit'` | When fields validate first. |
| `revalidate` | `ValidationMode` | `'input'` | When fields validate again after that. |
| `ui` | `Partial<Record<AutoFormSlot, string>>` | | Classes per theme slot. See [Theming](/auto-form/theming). |
| `class` | | | Classes for the root `<form>`. |

The form store is created once. To swap `schema` or reload `initial-input`, give the component a new `:key`, or call `reset(form, { initialInput })` on the exposed form.

## The form store

`<FAutoForm>` exposes its Formisch `form`, so every [method](/forms/methods) works on it:

```vue
<script setup lang="ts">
const autoForm = useTemplateRef('autoForm')

function prefill() {
  if (autoForm.value)
    setInput(autoForm.value.form, { path: ['email'], input: 'ada@example.com' })
}
</script>

<template>
  <FAutoForm ref="autoForm" :schema="ProfileSchema" @submit="save" />
</template>
```

The `actions` slot and `field:` slots get it as `form` too.

## Schema to input

| Schema | Renders |
| --- | --- |
| `v.string()` | `UInput`. `type="email"`, `"url"` or `"date"` with `v.email()`, `v.url()` or `v.isoDate()`. |
| `v.string()` with `type: 'textarea'` | `UTextarea` |
| `v.number()` | `UInput type="number"`, with `min`/`max` from `v.minValue()`/`v.maxValue()` and step `1` with `v.integer()`. |
| `v.boolean()` | `USwitch` |
| `v.picklist()`, `v.enum()`, a union of `v.literal()`s | `USelect` |
| `v.object()`, `v.looseObject()`, `v.strictObject()` | A fieldset with the nested fields. |
| `v.array()` | A list with add and remove buttons. |
| `v.record()`, `v.unknown()`, `v.any()`, or `type: 'json'` | A JSON `UTextarea`. |

`v.optional()`, `v.nullable()`, `v.nullish()` and `v.undefinedable()` make a field optional; every other field is marked required. `v.minLength()` and `v.maxLength()` become `minlength` and `maxlength` on the input.

## Labels and options from the schema

Without metadata, the label comes from the key: `firstName`, `first_name` and `first-name` all become "First Name". `v.title()` and `v.description()` set the label and help text, and `v.metadata()` sets the other field options, so they travel with the schema:

```ts
const ProductSchema = v.object({
  name: v.string(),
  price: v.pipe(
    v.number(),
    v.minValue(0),
    v.title('Price'),
    v.description('Before tax.'),
    v.metadata({ unit: 'USD', placeholder: '0.00', section: 'Pricing' }),
  ),
  notes: v.pipe(v.optional(v.string()), v.metadata({ type: 'textarea' })),
})
```

`v.metadata()` reads `label`, `description`, `placeholder`, `unit`, `section`, `order`, `hidden`, `colSpan`, `disabled` and `type`. The full list is under [Customization](/auto-form/customization#field-options).

## Nested objects and arrays

Objects render as fieldsets, arrays as repeatable rows. They nest as deep as the schema does, and array-level validation like `v.minLength(1)` shows under the list.

```ts
const TeamSchema = v.object({
  name: v.string(),
  address: v.object({
    city: v.string(),
    country: v.string(),
  }),
  members: v.pipe(
    v.array(v.object({
      name: v.pipe(v.string(), v.minLength(1)),
      role: v.picklist(['lead', 'developer', 'designer']),
    })),
    v.minLength(1, 'Add at least one member'),
  ),
  labels: v.record(v.string(), v.string()),
})
```

## Schema from data

When all you have is a JSON value, `jsonToValibotSchema` infers a schema from it. Keys get a humanized `v.title()`, and strings that look like emails, http(s) URLs, ISO dates or timestamps get the matching check:

```vue
<script setup lang="ts">
const settings = { retries: 3, endpoint: 'https://api.example.com', verbose: false, tags: ['beta'] }
const SettingsSchema = jsonToValibotSchema(settings)
</script>

<template>
  <FAutoForm :schema="SettingsSchema" :initial-input="settings" @submit="save" />
</template>
```

Values nested deeper than `maxDepth` (default `10`) become `v.any()`: `jsonToValibotSchema(value, { maxDepth: 3 })`.
