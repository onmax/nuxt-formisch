`<FAutoForm>` reads a Valibot object schema and renders a Nuxt UI input for each entry, with labels, descriptions, required markers and validation errors. It is registered when `@nuxt/ui` is installed.

```vue [app/pages/profile.vue]
<script setup lang="ts">
import * as v from 'valibot'

const ProfileSchema = v.object({
  name: v.pipe(v.string(), v.minLength(2)),
  email: v.pipe(v.string(), v.email()),
  age: v.pipe(v.number(), v.minValue(18)),
  role: v.picklist(['developer', 'designer', 'manager']),
  newsletter: v.boolean(),
})

function onSubmit(profile: v.InferOutput<typeof ProfileSchema>) {
  return $fetch('/api/profile', { method: 'PUT', body: profile })
}
</script>

<template>
  <FAutoForm :schema="ProfileSchema" @submit="onSubmit">
    <template #actions="{ isDirty, isSubmitting }">
      <UButton type="submit" :loading="isSubmitting" :disabled="!isDirty">
        Save
      </UButton>
    </template>
  </FAutoForm>
</template>
```

The submit button goes in the `actions` slot; AutoForm doesn't render one.

## Props

| Prop | Type | Default | |
| --- | --- | --- | --- |
| `schema` | Valibot object schema | | Required. |
| `initialValues` | `Record<string, unknown>` | | Starting values. |
| `fieldConfig` | `Record<string, FieldConfig>` | | Per-field overrides. See [Customization](/auto-form/customization). |
| `columns` | `1 \| 2 \| 3 \| 4` | `1` | Grid columns. Collapses to one column on small screens. |
| `disabled` | `boolean` | `false` | Disables every input. |
| `ui` | `{ root?, section?, sectionTitle?, grid? }` | | Classes per slot. See [Theming](/auto-form/theming). |

## Events

| Event | Payload |
| --- | --- |
| `submit` | The validated schema output. |
| `error` | `Record<string, string>`: the first message per dotted path, for example `{ 'address.zip': 'Invalid length' }`. |

## Schema to input

| Schema | Renders |
| --- | --- |
| `v.string()` | `UInput`. `type="email"` when the pipe has `v.email()`. |
| `v.number()` | `UInput type="number"`, with `min`/`max` from `v.minValue()`/`v.maxValue()`. |
| `v.boolean()` | `USwitch` |
| `v.picklist([...])`, `v.enum(...)` | `USelect` with the options. |
| `v.object({...})` | A bordered group with the nested fields. |
| `v.array(...)` | A list with add and remove buttons. |
| `v.record(...)` | A JSON `UTextarea`. |

`v.optional()`, `v.nullable()` and `v.nullish()` make a field optional; every other field is marked required. `v.minLength()` and `v.maxLength()` become `minlength` and `maxlength` on the input.

## Labels and help text

Without metadata, the label comes from the key: `firstName` becomes "First Name". Valibot's metadata actions set the rest, so the schema stays the single source:

```ts
const ProductSchema = v.object({
  price: v.pipe(
    v.number(),
    v.minValue(0),
    v.title('Price'),
    v.description('Before tax.'),
    v.metadata({ unit: 'USD', placeholder: '0.00', section: 'Pricing' }),
  ),
})
```

| Action | Sets |
| --- | --- |
| `v.title()` | Label |
| `v.description()` | Help text under the input. |
| `v.metadata({ placeholder })` | Placeholder |
| `v.metadata({ unit })` | A suffix next to the input, such as `kg` or `USD`. |
| `v.metadata({ section })` | Groups the field under a heading with other fields of the same section. |

## Nested objects and arrays

Objects render as groups, arrays of objects as repeatable groups, and arrays of scalars as a list of inputs. They nest as deep as the schema does.

```ts
const TeamSchema = v.object({
  name: v.string(),
  address: v.object({
    city: v.string(),
    zip: v.pipe(v.string(), v.length(5)),
  }),
  members: v.array(v.object({
    name: v.string(),
    email: v.pipe(v.string(), v.email()),
  })),
  tags: v.array(v.string()),
})
```

## Layout

`columns` lays fields out in a grid. Give a field `colSpan` in `fieldConfig` to widen it:

```vue
<FAutoForm
  :schema="ContactSchema"
  :columns="2"
  :field-config="{ message: { colSpan: 2 } }"
  @submit="onSubmit"
/>
```
