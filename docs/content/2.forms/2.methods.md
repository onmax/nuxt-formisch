Formisch keeps its API small by putting actions in plain functions instead of on the store. Each one takes the form store first and, when it needs one, a config object second:

```ts
getInput(form, { path: ['email'] })
setInput(form, { path: ['email'], input: 'ada@example.com' })
reset(form, { initialInput: { email: '', password: '' } })
move(form, { path: ['todos'], from: 0, to: 2 })
```

Reads are reactive, so `getInput(form)` inside a `computed` or a template updates with the form. Leave out `path` to act on the whole form.

## Read

| Method | Returns |
| --- | --- |
| `getInput` | The current input of a field or the form. |
| `getErrors` | The errors of one field, or of the root object. |
| `getDeepError` | The first error within a field or the form. |
| `getDeepErrors` | Every error within a field or the form. |
| `getDeepErrorEntry` / `getDeepErrorEntries` | The first / every error, paired with its field path. |
| `isTouched`, `isEdited`, `isDirty`, `isValid` | That state for one field, or for the whole form. |

## Dirty input

| Method | Returns |
| --- | --- |
| `getDirtyInput` | Only the parts of the input that differ from the initial input. Handy for `PATCH` requests. |
| `getDirtyPaths` | The paths of the dirty fields. |
| `pickDirty` | The dirty parts of another value, such as the validated output: `pickDirty(form, { from: output })`. |

## Write

| Method | Does |
| --- | --- |
| `setInput` | Sets the input of a field or the form. |
| `setErrors` | Sets or clears (`null`) the errors of a field, for example from a server response. |
| `reset` | Resets a field or the form. Pass `initialInput` to load new data, such as a fresh API response. |

Prefer `reset` with a new `initialInput` over `setInput` when the source data changed: it updates the baseline that `isDirty` compares against.

## Control

| Method | Does |
| --- | --- |
| `validate` | Validates the form and returns Valibot's result. `{ shouldFocus: true }` focuses the first invalid field. |
| `submit` | Submits the `<FForm>` from outside it, through `requestSubmit()`. |
| `handleSubmit` | Wraps a handler so it validates first. Use it when you can't render a `<form>`, for example inside another form. |
| `focus` | Focuses a field's element. |

```vue
<script setup lang="ts">
const form = useForm({ schema: LoginSchema })
const save = handleSubmit(form, values => $fetch('/api/login', { method: 'POST', body: values }))
</script>

<template>
  <!-- fields bound to `form`, no <FForm> -->
  <UButton :loading="form.isSubmitting" @click="save">Save</UButton>
</template>
```

## Arrays

| Method | Config |
| --- | --- |
| `insert` | `{ path, at?, initialInput? }`. Appends when `at` is left out. |
| `remove` | `{ path, at }` |
| `move` | `{ path, from, to }` |
| `swap` | `{ path, at, and }` |
| `replace` | `{ path, at, initialInput? }` |

See [useFieldArray](/forms/composables#usefieldarray) for a full list example. Each method is documented in detail in the [Formisch API reference](https://formisch.dev/vue/api/).
