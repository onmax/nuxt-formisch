Client validation is for the user. The server still has to check the body itself. `useFormValidation` is auto-imported in `server/` and does that with the same schema.

```ts [shared/utils/schemas.ts]
import * as v from 'valibot'

export const SignupSchema = v.object({
  email: v.pipe(v.string(), v.email()),
  password: v.pipe(v.string(), v.minLength(8)),
})
```

```ts [server/api/signup.post.ts]
export default defineEventHandler(async (event) => {
  // typed as v.InferOutput<typeof SignupSchema>
  const { email, password } = await useFormValidation(event, SignupSchema)
  // ...create the account
  return { email }
})
```

Schemas in `shared/utils/` are auto-imported in `app/` and `server/`, so neither file needs an import.

## Signature

```ts
function useFormValidation<T>(event: H3Event, schema: StandardSchemaV1<unknown, T>): Promise<T>
```

It reads the body with h3's `readValidatedBody` and returns the schema's output, with transforms applied. Any [Standard Schema](https://standardschema.dev) works, so a Zod or ArkType schema is accepted too, though forms themselves need Valibot.

## Errors

An invalid body throws a `400` error. The Standard Schema issues are in `data.issues`:

```json
{
  "statusCode": 400,
  "statusMessage": "Validation Error",
  "message": "Form validation failed",
  "data": {
    "issues": [{ "message": "Invalid email: Received \"ada\"", "path": [{ "key": "email" }] }]
  }
}
```

Errors that only the server can know, like a taken email, go back to the field with `setErrors`:

```ts [app/pages/signup.vue]
const form = useForm({ schema: SignupSchema })

const onSubmit: SubmitHandler<typeof SignupSchema> = async (values) => {
  const { taken } = await $fetch('/api/signup/check', { query: { email: values.email } })
  if (taken)
    return setErrors(form, { path: ['email'], errors: ['This email is already registered.'] })
  await $fetch('/api/signup', { method: 'POST', body: values })
}
```
